# 독립 로컬 웹 도구로 코드 구조 탐색

2026-10-13 사용자와 합의했다. jelly-flow는 대상 프로젝트에 복사하는 스킬을 주된 사용 방식으로 삼는 대신, 다른 프로젝트를 지정해 분석·탐색·재분석하는 독립 로컬 웹 도구로 발전시킨다. 그래프에서 구조 검토 후보를 찾고 대상 프로젝트에서 리팩터링한 뒤 다시 분석하는 흐름을 지원하기 위해, 로컬 서버의 실행·관리 비용을 받아들인다.

초기 탐색 관계는 Imports와 Possible calls이며, 목적은 의존성 집중·순환·책임 집중 같은 구조 검토 후보를 찾는 것이다. 실제 실행 시간에 따른 성능 병목 진단이나 자동 리팩터링은 이 목적에 포함하지 않는다. 코드를 수정하는 작업은 대상 프로젝트에서 수행한다.

파일을 기본 노드로 두고 선택한 파일의 함수를 펼친다. 폴더별 고정 격자에서 관계에 따라 배치되는 그래프로 바꾸며, 넓은 그래프 공간, 왼쪽 필터, 관계별 색과 필터, 노드 드래그를 제공하는 방향에 합의했다. 상속·구현·문서·ADR 관계의 수집은 초기 범위에 추가하지 않는다.

## 합의한 사용 흐름

필요할 때 jelly-flow에서 명령 하나로 실행하는 개인용 로컬 웹 도구로 제공한다. 실행 명령을 종료하면 서버도 종료한다. 대상 프로젝트에 별도 설치나 설정 파일을 요구하지 않고 jelly-flow가 프로젝트 설정과 분석 결과를 관리하며, 저장한 프로젝트를 다시 선택할 수 있게 한다.

프로젝트 경로를 입력하면 진입점과 분석 범위를 자동 제안하고, 사용자가 확인·수정한 설정을 프로젝트별로 저장한다. 확인되지 않은 영역은 표시하여 분석 범위를 알 수 있게 한다.

첫 버전은 사용자가 버튼을 눌러 수동 재분석한다. 분석 시점을 표시하고 재분석 중에도 이전 그래프를 볼 수 있게 하며, 완료 후 새 결과로 교체할 때 선택한 파일과 화면 위치를 가능한 한 유지한다. 최신 구조의 탐색을 우선하며, 추가·삭제된 연결을 보여주는 전후 비교 화면은 후속 범위로 둔다.

재분석이 실패하거나 일부만 완료되면 이전 결과를 유지하고 이전 분석 결과임을 명시한다. 새 분석의 실패·누락 범위를 보여주며, 유효한 부분 결과가 있으면 사용자가 선택하여 전환할 수 있게 한다. 이전 결과를 현재 소스의 결과로 표시하거나, 분석 누락 때문에 사라진 연결을 리팩터링 효과로 설명하지 않는다.

연결이 집중된 파일과 순환 관계를 목록으로 제공하며, 항목을 선택하면 그래프에서 해당 부분을 강조한다. 호출하는 파일 수, 호출받는 파일 수, 순환에 참여한 관계를 각각 제시하고 하나의 결함 점수로 합치지 않는다.

선택한 부분의 파일·함수·소스 위치, 연결과 관계 종류, 분석 시점을 검토 근거로 복사할 수 있게 한다. 사용자가 대상 프로젝트의 에이전트에게 이 자료를 전달하여 실제 코드를 검토하는 흐름이다.

## 기존 결정의 재검토

[GitHub 명세 #1](https://github.com/kalstein00/jelly-flow/issues/1)의 복사 가능한 스킬 중심 사용 방식과 서버 없는 오프라인 HTML 중심 제품 형태를 재검토한다. 기존 명세의 상시 서비스 제외 범위를 새 로컬 웹 도구 전체에 그대로 적용할 수는 없다. 첫 버전은 필요할 때 실행하는 서버와 수동 재분석을 제공하며, 기존 오프라인 HTML 생성 기능은 유지한다.

기존 분석기, Imports와 Possible calls의 구분, 미분석·부분 결과의 명시, 입력 변경에 따른 결과 재사용 검증은 활용한다. 이 ADR은 방향에 대한 합의이며 웹 도구의 구현 완료나 기존 이슈의 변경을 뜻하지 않는다.
